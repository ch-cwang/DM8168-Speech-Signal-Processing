# DM8168 异构多核音频流控系统需求分析文档 (Requirements Analysis)

## 1. 项目背景 (Background)
DM8168 是一款强大的异构多核处理器，内含 ARM Cortex-A8 (负责 OS 和外设调度) 和 C674x DSP (负责高强度数学运算)。在智能语音分析、工业声学监测等领域，通常需要 DSP 介入处理原始的麦克风音频流。
本项目旨在为这两种架构之间搭建一座**极低延迟、绝对连续、免互斥锁**的音频数据传输高架桥，从而把 DSP 端完全剥离出来，使其成为一个纯粹的“算法黑盒”。

---

## 2. 功能性需求 (Functional Requirements)

### 2.1 高保真音频全双工透传
*   **采样率支持**：系统必须强制锁定为 **48,000 Hz**。
*   **位深与通道**：支持 **Signed 16-bit Little Endian (S16_LE)** 与 **双声道 (Stereo)**。
*   **全双工能力**：必须同时开启录音 (Capture) 与播放 (Playback) 数据流，形成 `外设 -> ARM -> DSP -> ARM -> 外设` 的完整闭环。

### 2.2 零拷贝双核通信 (Zero-Copy Inter-Core Communication)
*   **消除内存拷贝**：严禁在 ARM 和 DSP 之间使用消耗 CPU 资源的拷贝操作（如 TCP/IP 虚拟网卡，或管道传值）。必须通过预先在非 Cache 一致性区域 (`SHARED_REGION_1`) 划分共享物理内存的方式，实现指针级的数据移交。

### 2.3 算法植入留白 (Algorithm Placeholder)
*   **DSP 纯粹化**：DSP 端代码不得包含任何外设驱动逻辑。必须暴露出一个纯净的、仅基于指针和长度的算法处理入口（如 `DSP_Process(char* in, char* out, int len)`），以便后续平滑植入 AEC、AGC、均衡器等重型声学算法。

## 3. 非功能性需求 (Non-Functional Requirements)

### 3.1 极限抗撕裂与抗抖动能力 (Anti-tearing & Anti-jitter)
**背景**：Linux 并非硬实时操作系统，在面临网络 IO、SD卡读写、乃至 CPU 满载时，其线程调度会出现数十毫秒的停滞。
*   **需求 1 (超深缓冲池)**：系统底层 DMA 缓冲深度必须达到 **400 毫秒** (即 20 个 20ms 周期)，以应对 Linux 调度引发的极端抖动。
*   **需求 2 (残缺帧拼装)**：即使 ALSA 因内核压力单次吐出残缺的音频片段，系统代码也必须在内部进行**偏移量拼装 (Offset Assembly)**。严禁将任何发生位移的残块发往 DSP，确保波形相位的绝对连续性。

### 3.2 冷启动爆音抑制 (Underrun Pop Prevention)
*   **需求**：系统启动的最初 1 秒内，由于数据流尚未稳定，极易出现扬声器因为缺数据而导致的尖锐“叭”声（数字爆音）。
*   **解决指标**：必须实现**预充水机制**。强制要求底层声卡引擎在积攒至少 **60 毫秒 (3 个周期)** 的音频数据后，方可启动发声，从根源上杜绝初期 DMA 饥饿。

### 3.3 无死锁的安全退出机制 (Graceful Teardown)
**背景**：双核 IPC 共享着严苛的硬件中断寄存器和内存。
*   **需求**：在用户按下 `Ctrl+C` 强杀进程时，系统不能产生“僵尸进程”。必须能够在 1 秒内完成：
    1.  击破所有正在死等的内核空间阻塞 (ALSA IO)。
    2.  通知 DSP 退出死循环计算。
    3.  接收 DSP 的死亡确认 (ACK)。
    4.  彻底注销硬件中断并返还共享内存给 Linux OS。
*   **指标**：允许无限次的高频脚本自动化启停，系统绝不发生第二次无法启动的死锁状况。
