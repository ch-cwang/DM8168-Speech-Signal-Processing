# 软件需求规格说明（SRS）

## 1. 引言

### 1.1 目的

本文档描述基于 TI DM8168 的双核音频处理系统的功能与非功能需求，作为后续设计与验收的依据。

### 1.2 范围

系统在 ARM（Linux）与 DSP（SYS/BIOS）之间实现实时音频流的采集、处理与播放，DSP 端预留算法处理接口。

## 2. 系统概述

系统由外部音频编解码器（ADC/DAC）、ARM 端应用、DSP 端固件与跨核共享内存构成。数据流向为：采集 → ARM → DSP → ARM → 播放。

## 3. 功能需求

| 编号 | 需求描述 |
|------|----------|
| FR-1 | 系统支持 48 kHz、双声道、16 位小端（S16_LE）音频采集与播放。 |
| FR-2 | ARM 与 DSP 之间通过共享内存传递音频数据，核间不做逻辑拷贝。 |
| FR-3 | 每 20 ms（960 帧）完成一次数据块采集、处理与输出，形成连续音频流。 |
| FR-4 | DSP 对每块数据执行处理（当前为直通 `memcpy`），处理结果写回共享内存供播放。 |
| FR-5 | 支持通过回车键触发系统优雅退出，完整释放共享内存、信号量与 ALSA 句柄。 |

## 4. 非功能需求

| 编号 | 类别 | 需求描述 |
|------|------|----------|
| NFR-1 | 实时性 | 单块处理周期 20 ms；共享内存缓冲深度 400 ms，可容忍 300 ms 内的调度延迟。 |
| NFR-2 | 可靠性 | 在 CPU 满载时不得出现音频帧错位或撕裂。 |
| NFR-3 | 稳定性 | 频繁启停 10 次以上不得发生死锁、资源泄漏或 IPC 占用。 |
| NFR-4 | 可移植性 | 通过环境变量解耦 ALSA 路径与 DSP 平台，支持跨平台移植。 |

## 5. 约束与假设

- 硬件平台为 TI DM8168，兼容 OMAP-L138。
- 音频输入输出为 3.5 mm Line In 与耳机接口。
- 开发套件为 TI SYS/BIOS、XDCtools 与 SysLink/IPC。
